# cavan-statistics

Расширение для Chrome: собирает продажи из личного кабинета
[Cavan Images](https://www.cavanimages.com) и показывает, сколько принесла
каждая фотография и каждая съёмка. Построено на React по архитектуре
[bulletproof-react](https://github.com/alan2207/bulletproof-react).

## Установка

```bash
npm install
npm run build
```

1. Откройте `chrome://extensions` и включите **Режим разработчика**.
2. Нажмите **Загрузить распакованное расширение** и выберите папку `dist`.
3. После каждой новой сборки нажмите на карточке расширения кнопку ↻.

## Как пользоваться

1. Войдите в аккаунт на cavanimages.com в этом же Chrome.
2. Нажмите на значок расширения — откроется вкладка со статистикой.
3. Нажмите **Загрузить данные**. Первый сбор занимает несколько минут: запросы идут по одному с паузой 1–2
   секунды, чтобы не нагружать Cavan. Вкладки не закрывайте. Дальше
   кнопка «Добавить новые месяцы» скачивает только новое (последние месяцы, историю
   проданных в них фото и новые съёмки) — это 20–30 запросов. «Полное
   обновление» скачивает всё заново.

Данные хранятся только в браузере (`chrome.storage.local`) и никуда не отправляются.

## Как это работает

Расширение выполняет запросы в открытой вкладке cavanimages.com (`chrome.scripting`,
`world: "MAIN"`), поэтому они идут с вашей сессией и CSRF-токеном — так же, как
запросы самого сайта. Используются те же JSON-эндпоинты, что и страницы кабинета:

| Эндпоинт                                            | Данные                                  |
| --------------------------------------------------- | --------------------------------------- |
| `/account/photographer/api/sales` `overview`        | общий доход и число загрузок            |
| `/account/photographer/api/sales` `month`           | продажи за месяц (ID фото, сумма)       |
| `/account/photographer/api/sales` `product-history` | все продажи одного фото с партнёром     |
| `/account/ingest/api/list`                          | список завершённых съёмок (submissions) |
| `/account/ingest/api/fetch-batch`                   | опубликованные файлы одной съёмки       |
| `/account/library/api/fetch`                        | весь портфель (Portfolio Manager)       |
| `/account/photographer/api/stats`                   | размер портфеля (Dashboard)             |

Фото связываются со съёмкой через портфель: в его имени файла на Cavan
(`CR_<код съёмки>-<ID файла заявки>-01.jpg`) зашит номер файла из заявки
Submit Content, а у каждого фото есть ID съёмки Cavan. Старые съёмки, заявок
которых в Submit Content нет, собираются по ID съёмки Cavan и называются её
кодом (например, `KSLI211019`); их можно переименовать. Если одна фотосессия
загружена на Cavan несколькими частями, части можно объединить: в строке
съёмки выберите «Присоединить к этой съёмке» (отсоединить можно там же). Если фото нет в
портфеле, используется запасной вариант — совпадение исходного имени файла.

Фото, которые связать не удалось, попадают в строку «Без съёмки». Там их
можно отметить галочками и собрать в свою съёмку с любым названием. Свои
съёмки хранятся отдельно от данных Cavan, поэтому повторное обновление их не
сбрасывает. У своих съёмок известны только проданные фото, поэтому столбцы
«Опубл. фото» и «На 1 фото» для них пустые.

## Разработка

| Команда                | Описание                                     |
| ---------------------- | -------------------------------------------- |
| `npm run dev`          | Dev-сервер Vite (без API Chrome — только UI) |
| `npm run build`        | Проверка типов (`tsc -b`) и сборка в `dist`  |
| `npm run lint`         | Запустить ESLint                             |
| `npm run lint:fix`     | ESLint с автоисправлением                    |
| `npm run format`       | Отформатировать код через Prettier           |
| `npm run format:check` | Проверить форматирование без изменений       |

Папка `samples/` — сохранённые страницы и ответы Cavan для разработки. Она в
`.gitignore`: там личные данные.

## Структура проекта

Проект следует структуре папок bulletproof-react:

```
src/
├── app/              # слой приложения — связывает всё воедино
│   ├── routes/       # компоненты маршрутов
│   ├── app.tsx       # корневой компонент (провайдеры + роутер)
│   ├── provider.tsx  # глобальные провайдеры (error boundary и т.п.)
│   └── router.tsx    # конфигурация роутера
├── assets/           # статические файлы (иконки, изображения, шрифты)
├── components/       # общие переиспользуемые компоненты
│   ├── ui/           # компоненты дизайн-системы (button, modal, …)
│   ├── layouts/      # компоненты-раскладки
│   └── errors/       # error boundary / фолбэки
├── features/         # модули-фичи (самодостаточные)
├── hooks/            # общие хуки
├── lib/              # преднастроенные библиотеки (например, API-клиент)
├── stores/           # глобальные хранилища состояния
├── styles/           # глобальные стили и Sass-переменные
├── types/            # общие типы TypeScript
└── utils/            # общие утилиты
```

Модуль-фича (`src/features/<feature>/`) самодостаточен и может содержать
собственные `api/`, `components/`, `hooks/`, `stores/`, `types/` и `utils/`.

## Правила архитектуры

Кодовая база **однонаправленная** — импорты могут идти только в одну сторону:

```
общие слои  →  features  →  app
```

- **Общие** слои (`components`, `hooks`, `lib`, `stores`, `types`, `utils`)
  не могут импортировать из `features` и `app`.
- **Features** не могут импортировать из `app` и не должны обращаться к другим
  фичам — композиция фич выполняется в слое `app`.

Эти правила **enforce'ятся ESLint** (`no-restricted-imports` в `eslint.config.js`);
их нарушение проваливает линтинг. Для абсолютных импортов из `src/` используйте
алиас `@/` (например, `import { Button } from '@/components/ui/button'`), а внутри
одной фичи — относительные импорты.
